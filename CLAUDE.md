# Método Vikingo — notas para Claude Code

- Landing de venta directa, **una sola página** (`app/page.tsx`). Next.js 16 (App Router), React 19, Tailwind v4 (`@theme` en `app/globals.css`, tokens de marca: `bg/bg-2/bg-3`, `ink/ink-dim/ink-faint`, `ember/ember-2/ember-deep`, `line`, `cream`/`cream-ink`, `ice`, `ok`/`err` — los nombres `ember*` se mantuvieron aunque el valor de marca pasó de carmesí a naranja brasa, para no tocar cada clase `bg-ember`/`text-ember-2` del proyecto). Fuente única: Poppins (`font-display` = `font-sans`), 500/600 texto y 700/800 titulares.
- Estilo "taberna vikinga": tarjetas oscuras con borde de color de 3px (`.card-vikingo`, variantes `-ice`/`-err`), tarjetas claras para precio/resúmenes (`.card-crema`), pills (`.pill`), botón "3D de caricatura" con sombra sólida inferior que se aplana al pulsar (`.btn-viking`). Brasas de fondo (`app/components/Embers.tsx`, canvas fijo a 30 fps, se pausa fuera de pantalla y con `prefers-reduced-motion`). Mascota del Método en `app/components/VikingMascot.tsx` (PNGs en `public/vikingo/`, 8 poses) — máximo una por sección, nunca deformarla/recolorarla.
- Animaciones con `framer-motion`: `Reveal`/`Stagger` (entrada con rebote al hacer scroll), `ExitPopup` (una vez por sesión, sin descuento ni fecha límite inventados), `StickyCTA` (barra con precio + botón). Todo respeta `prefers-reduced-motion` (brief original en `ESTILO_Y_SECCIONES.md`, ya aplicado — no reintroducir animaciones que lo ignoren).
- Iconos: `lucide-react` en todo el sitio — nunca emojis como ícono de sección.
- FAQ: `app/components/Acordeon.tsx` anima el alto con el truco CSS `grid-template-rows: 0fr → 1fr` (clase `.acordeon-contenido` en `globals.css`), no `<details>` nativo (no anima consistente entre navegadores) ni JS de altura.
- **Sin base de datos, sin auth, sin backend propio.** Se eliminó por completo el reto de 30 días gratuito (racha, notificaciones, Supabase, cron jobs, PDFs) para quedarse solo con esta landing — decisión explícita del producto, no reintroducir esa arquitectura sin que se pida.
- **Cero anuncios en todo el sitio.** Es una página de venta: el único camino es comprar o irse, cualquier distracción le resta a una conversión que vale mucho más que cualquier impresión publicitaria.
- El único CTA es `app/components/BotonHotmart.tsx`, que trackea el clic (`clic_hotmart`, con `ubicacion`: hero/precio/cta_final) vía Vercel Analytics (`<Analytics />` en `app/layout.tsx`) — es la métrica que decide si el proyecto genera dinero, nunca quitarla sin reemplazarla. El mismo clic dispara `InitiateCheckout` al pixel de TikTok si está configurado.
- Pixel de TikTok en `app/components/TikTokPixel.tsx` (montado en `layout.tsx`), controlado por `NEXT_PUBLIC_TIKTOK_PIXEL_ID` — vacío = no carga. El pixel de la landing solo ve PageView + InitiateCheckout; la conversión de compra real ocurre en Hotmart y se mide desde la integración TikTok del propio Hotmart, no desde aquí.
- **Nunca inventar precio, garantía o testimonios.** `NEXT_PUBLIC_PRECIO` y `NEXT_PUBLIC_GARANTIA_DIAS` controlan si esas secciones se muestran — si están vacías, la sección se omite en vez de mostrar un número o una cita fabricada. Mismo principio para testimonios: no agregar citas de clientes inventadas, solo reales cuando existan.
- `NEXT_PUBLIC_HOTMART_URL` tiene como fallback el checkout real (`BotonHotmart.tsx` → `HOTMART_URL_DEFAULT`, **nunca** la home genérica `hotmart.com`); `NEXT_PUBLIC_PRECIO` (solo el número, fallback "$18.99") y `NEXT_PUBLIC_PRECIO_MONEDA` (sigla, fallback "USD") tienen fallback real. `NEXT_PUBLIC_PRECIO_ANTERIOR` no tiene fallback — si no hay un valor real configurado, la sección de precio no muestra ningún tachado. Actualizar esos defaults si el precio o el link cambian, en vez de dejarlos desactualizados.
- **Copy prohibido, aunque se pida explícitamente**: (1) instruir a menores de edad a comprar sin un adulto ("pídele a tus padres o a un amigo, es 100% legal") — no es mi lugar afirmar eso y es apuntar a comprar sin supervisión; (2) un precio tachado "de antes" que sea inventado — solo mostrar un precio anterior si fue real (usar `NEXT_PUBLIC_PRECIO_ANTERIOR`, nunca hardcodear uno); (3) escasez falsa tipo "cupos limitados" en un producto digital de stock infinito; (4) lenguaje de "garantía"/"sin riesgo" sin un reembolso real detrás. La sección de pago en efectivo (OXXO/Efecty/Nequi/etc.) sí es legítima y se queda — es real y útil para cualquier persona sin tarjeta en LatAm, no solo menores.
- Un solo camino por página (comprar o salir) — sin nav, sin menú, footer mínimo con solo el link de `/privacidad`. `StickyCTA.tsx` usa `IntersectionObserver` sobre el sentinel `#fin-hero`, no scroll listeners.
- Idioma de UI y comentarios: español.
- Verificar con `npm run lint` y `npm run build`. Si `tsc`/`next build` fallan con módulos de rutas que ya no existen, es cache de `.next/types` — borrar `.next/` y reintentar.
