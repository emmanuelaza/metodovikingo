# Reto Vikingo — notas para Claude Code

- Next.js 16 (App Router, `proxy.ts` en vez de middleware), React 19, Tailwind v4 (`@theme` en `app/globals.css`, tokens de marca: `bg/bg-2/bg-3`, `ink/ink-dim/ink-faint`, `ember/ember-2/ember-deep`, `line`). Fuentes: Anton (`font-display`) para títulos, Manrope (default) para texto. `params`/`searchParams` son Promises.
- Idioma de UI y comentarios: español. Diseño full-bleed (sin `max-w-lg` global): `app/layout.tsx` no restringe ancho, cada página arma su propio contenedor (franja de header + `max-w-3xl`/`max-w-4xl` interno).
- **Sin registro visible**: la auth es anónima (`supabase.auth.signInAnonymously()` en `lib/supabase/middleware.ts`, primera visita). No reintroducir landing, "palabra de entrada", magic link ni formularios de registro sin que el usuario lo pida explícitamente — es una decisión de producto tomada a propósito.
- **El desbloqueo de días es puro cálculo por calendario**, nunca por acción del usuario: `diaMaximoDisponible()` en `lib/progreso.ts` a partir de `profiles.fecha_inicio`. No hay `current_day` guardado ni RPC de "completar día" — no reintroducir ese patrón.
- El checkbox "marcar como completado" (`app/reto/[dia]/actions.ts`) es solo seguimiento personal: un insert/delete simple en `daily_completions` protegido por RLS, no un gate. No hace falta `security definer` para esto.
- La racha se calcula leyendo fechas de `daily_completions` (`calcularEstadoCurso` en `lib/progreso.ts`), no se guarda como contador. No hay mecánica de "recuperar racha".
- La fecha "hoy" viene de `lib/fecha.ts` (`hoyISO()`, zona `RETO_TIMEZONE`).
- Texto de lecciones/piezas/fases: `lib/contenido.ts` (Sanity con fallback a `content/*-seed.ts`). No hardcodear lecciones en páginas.
- **El temario está agrupado en 5 fases** (`content/fases-seed.ts`, tipo Sanity `fase`). Cada lección tiene estructura fija: `introduccion`, `concepto`, `rutinaTitulo` + `rutinaItems` (concreto: series/repeticiones o comidas con horario, nunca teoría genérica), `tipAccionable`, `previewSiguiente`. No volver a un formato de párrafos libres/Portable Text para lecciones sin que se pida.
- Las "piezas" del Método Secreto ahora son las **Runas** (días 7/14/21, revelación completa día 30) — mismo tipo `Pieza` en el código, copy temático distinto (`content/piezas-seed.ts`).
- Anuncios: **Adsterra, Popunder + Social Bar** inyectados una sola vez en `app/layout.tsx` (`next/script`, `strategy="afterInteractive"`, no bloquean el render). Al vivir en el root layout, que no se remonta en navegación client-side, cargan una sola vez por sesión de navegación, no en cada cambio de ruta — no mover estos scripts a un componente que sí se remonte. Apagar todo con `NEXT_PUBLIC_ADS_ENABLED=false`.
- Descarga de PDF por día: `lib/pdfsReto.ts` (`pdfDelDia`) busca el archivo en `public/pdfs/fase-X/` por el prefijo `dia-NN-` (no hardcodear los 30 nombres — el resto del nombre puede variar). El gate de descarga (`app/components/DescargaPdfDia.tsx`) es honesto a propósito: el botón dice desde el inicio que hay un anuncio, abre el Smartlink en pestaña nueva y arranca una cuenta regresiva visible; al llegar a 0 se habilita la descarga real sin verificar si el usuario interactuó con el anuncio — no agregar lenguaje engañoso tipo "verificando seguridad" ni bloquear el flujo si no interactuó.
- Discord y el carrusel de testimonios (`TestimoniosCarrusel.tsx`, temario y días 19/26) ya están construidos — Discord sigue siendo placeholder "Próximamente" a propósito, no construirlo sin que se pida.
- Notificaciones: Web Push nativo (no Firebase), `lib/push/*`. `public/sw.js` es el service worker. El prompt (`NotificacionesPrompt.tsx`) se muestra una sola vez tras completar el día 1, nunca de entrada. Dos crons diarios (`vercel.json`, protegidos con `CRON_SECRET`, usan `lib/supabase/admin.ts` — service_role, único lugar que la necesita): `app/api/cron/notificar` (mañana) avisa el día que se acaba de habilitar; `app/api/cron/recordatorio-noche` (noche) manda uno de dos avisos honestos por usuario, nunca los dos — racha en riesgo (tiene racha activa y no completó el día de hoy) o recordatorio de registrar progreso (solo domingos, si no hay registro en 7+ días). Nunca inventar una amenaza/urgencia falsa — solo consecuencias reales de mecánicas que ya existen.
- El efecto "reveal" (chispas ember) y la vibración al marcar completado viven en `app/components/MarcarCompletado.tsx` (client component) — solo se disparan al marcar, nunca al desmarcar, y el form sigue funcionando como Server Action normal.
- `sanity/` está excluido del typecheck (importa el paquete `sanity`, que vive en el Studio aparte).
- Verificar con `npm run lint` y `npm run build`. Si `tsc`/`next build` fallan con módulos de rutas que ya no existen (p. ej. `app/dashboard`), es cache de `.next/types` — borrar `.next/` y reintentar.
