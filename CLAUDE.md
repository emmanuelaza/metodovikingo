# Método Vikingo — notas para Claude Code

- Landing de venta directa, **una sola página** (`app/page.tsx`). Next.js 16 (App Router), React 19, Tailwind v4 (`@theme` en `app/globals.css`, tokens de marca: `bg/bg-2/bg-3`, `ink/ink-dim/ink-faint`, `ember/ember-2/ember-deep`, `line` — los nombres `ember*` se mantuvieron aunque el valor de marca es carmesí `#e63946`, no naranja, para no tocar cada clase `bg-ember`/`text-ember-2` del proyecto). Fuentes: Oswald (`font-display`) para títulos, Inter (default) para texto.
- Iconos: set propio estilo Lucide/Feather en `app/components/IconosNordicos.tsx`, SVG inline (cero peso de red, cero CLS) — nunca usar emojis como ícono de sección, solo como acento puntual en copy/CTA si aplica.
- FAQ: `app/components/Acordeon.tsx` anima el alto con el truco CSS `grid-template-rows: 0fr → 1fr` (clase `.acordeon-contenido` en `globals.css`), no `<details>` nativo (no anima consistente entre navegadores) ni JS de altura.
- **Sin base de datos, sin auth, sin backend propio.** Se eliminó por completo el reto de 30 días gratuito (racha, notificaciones, Supabase, cron jobs, PDFs) para quedarse solo con esta landing — decisión explícita del producto, no reintroducir esa arquitectura sin que se pida.
- **Cero anuncios en todo el sitio.** Es una página de venta: el único camino es comprar o irse, cualquier distracción le resta a una conversión que vale mucho más que cualquier impresión publicitaria.
- El único CTA es `app/components/BotonHotmart.tsx`, que trackea el clic (`clic_hotmart`, con `ubicacion`: hero/precio/cta_final) vía Vercel Analytics (`<Analytics />` en `app/layout.tsx`) — es la métrica que decide si el proyecto genera dinero, nunca quitarla sin reemplazarla.
- **Nunca inventar precio, garantía o testimonios.** `NEXT_PUBLIC_PRECIO` y `NEXT_PUBLIC_GARANTIA_DIAS` controlan si esas secciones se muestran — si están vacías, la sección se omite en vez de mostrar un número o una cita fabricada. Mismo principio para testimonios: no agregar citas de clientes inventadas, solo reales cuando existan.
- `NEXT_PUBLIC_HOTMART_URL` tiene como fallback el checkout real (`BotonHotmart.tsx` → `HOTMART_URL_DEFAULT`, **nunca** la home genérica `hotmart.com`); `NEXT_PUBLIC_PRECIO` (solo el número, fallback "$23.00") y `NEXT_PUBLIC_PRECIO_MONEDA` (sigla, fallback "USD") tienen fallback real. `NEXT_PUBLIC_PRECIO_ANTERIOR` no tiene fallback — si no hay un valor real configurado, la sección de precio no muestra ningún tachado. Actualizar esos defaults si el precio o el link cambian, en vez de dejarlos desactualizados.
- **Copy prohibido, aunque se pida explícitamente**: (1) instruir a menores de edad a comprar sin un adulto ("pídele a tus padres o a un amigo, es 100% legal") — no es mi lugar afirmar eso y es apuntar a comprar sin supervisión; (2) un precio tachado "de antes" que sea inventado — solo mostrar un precio anterior si fue real (usar `NEXT_PUBLIC_PRECIO_ANTERIOR`, nunca hardcodear uno); (3) escasez falsa tipo "cupos limitados" en un producto digital de stock infinito; (4) lenguaje de "garantía"/"sin riesgo" sin un reembolso real detrás. La sección de pago en efectivo (OXXO/Efecty/Nequi/etc.) sí es legítima y se queda — es real y útil para cualquier persona sin tarjeta en LatAm, no solo menores.
- Diseño: tema "cinemático oscuro" — obsidiana (`#0a0a0c`/`#111115`/`#17171b`) + acento carmesí (`#e63946`), un solo camino por página (comprar o salir) — sin nav, sin menú, footer mínimo con solo el link de `/privacidad`. `StickyCTA.tsx` usa `IntersectionObserver` sobre el sentinel `#fin-hero`, no scroll listeners.
- Idioma de UI y comentarios: español.
- Verificar con `npm run lint` y `npm run build`. Si `tsc`/`next build` fallan con módulos de rutas que ya no existen, es cache de `.next/types` — borrar `.next/` y reintentar.
